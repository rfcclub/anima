# Recall hook session deduplication

`identity-client.ts hook` uses the host's `session_id` to suppress memory bodies it already emitted. It applies after relevance filtering and before rendering. Runtime `##` sections, Hindsight lines and local fallback lines share the same hash set. Retrieval score/timestamp/id envelope fields and whitespace do not change the hash; content-bearing numbers and dates do.

State lives in `recall-seen/<session_id>.json` beside the configured `IDENTITY_SESSION_PATH`. IDs must match `[A-Za-z0-9_-]{1,128}`. Missing or invalid IDs retain the previous output and create no seen-state. This is a host-provided session key, not an authentication credential or a new identity-runtime authorization mechanism. The separate Windows PowerShell hook does not use this mechanism.

Each file holds the 500 most recently emitted body hashes and at most five complete, non-sensitive bodies of at most 600 characters. Directory permissions are 0700 and files 0600. Writes use an exclusive session lock and atomic replacement. State older than two days is removed on the next valid hook call, including stale locks. Corrupt, oversized (>128 KiB), symlinked or inaccessible state, lock contention and failed commits restore the entire legacy output. Concurrent turns may therefore repeat a memory instead of losing it. Cleanup is opportunistic; an idle installation does not run a background eraser.

When a decision-provider API key is configured and `IDENTITY_HOOK_JEV` is not `0`, one additional decision request may compare unseen short public bodies against the five recent bodies from that same session. It sends at most 32 candidates, has a 2000 ms deadline, and does no retries. Empty, over-budget, timed-out or invalid/partial decisions keep all exact-layer survivors. A `duplicate` choice with probability at least 0.8 is a fixed threshold, not a guarantee of semantic accuracy. Long bodies use complete hashes only, so matching clipped prefixes cannot discard changed tails. Relevance requests have their own budget; “one” refers to this dedup layer.

The sensitive-terms guard checks the original full item before clipping, checks the normalized body, and rechecks saved recent text before sending it. Sensitive or unclassifiable items use hashes only. The guard is a term list: personal material matching no listed term can be saved for two days and sent to the decision provider. Runtime sections, Hindsight text and local text all take part in this decision path, which is enabled only by the API key. `IDENTITY_HOOK_JEV=0` disables both decision clients; it does not erase existing files or disable storage of short non-sensitive recent text.

Only emitted items enter the store. A section excluded entirely by the runtime cap stays eligible later; a partly clipped section counts as seen. Runtime output has a 600-character body cap and an 1800-character formatted-content cap, applied per section. After compaction or clear the hook receives no reset signal, so hashes remain until eviction or expiry.
