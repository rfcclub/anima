# Design: work-adapter-trial

## Architecture

Use the existing work handler, fake runner, SQLite store and host publisher ports for deterministic lifecycle decisions. Test a successful completion, deadline, host abort, named startup refusal and host publish refusals against these ports. Use existing work-store and GitHub public lifecycle information for comparison. Preserve the distinction between host logic verified by fakes and an actual VM boundary verified with an isolated scratch fixture.

Add an opt-in scratch runner. Require an explicit live flag and a fresh generated scratch repository with no remote, a dedicated process prefix and local synthetic fixtures. Stop before VM creation if prerequisites are missing. Use synthetic read/write canaries outside the mounted root, a throwaway sibling Git directory, a synthetic credential-shaped sentinel and a controlled local listener. Never point probes at real credential stores or unrelated services. Verify fixture contents before and after each run. Capture terminal result and verified process cessation independently. Clean up only resources minted by this invocation. A refused prerequisite is `not run` with a reason, and a failed assertion or failed cleanup is `fail`. Generated evidence remains local.

Run two Low sessions concurrently, then four only under the approved configured cap. Each uses a distinct workspace and gateway. From a controlled client, verify that one session's token is rejected by the other without logging either token. Keep the accepted fixture transcript and actual worker logs outside the repository. For resume, wait for #410 and record both ended-session and next-session evidence, including the continued tree/covered note and prior VM absence. Deadline provenance and programmer rules rely on the relevant #419 slices. No live scenario is considered observed during design.

## Loop author lanes and substrate

Continue to use the Mesh work consumer for pull, lease, cooldown and failure handling. Give each registered author one logical lane. Run at most one claimed work per author under the shared cap. The lane encloses context loading and the entire work session, releases the author slot on settlement, and lets the next polling cycle continue after an isolated failure. The current scheduler guarantees logical serialization, and a logical lane does not establish the owner's one-worker, one-thread requirement. Before the real comparison, the owner must explicitly choose whether same-process asynchronous lanes satisfy the requirement. Keep the real comparison blocked pending that decision. If the requirement means an actual worker thread, prepare and approve a separate threaded-lane design before enabling the trial. That design must verify author affinity, host-owned lease and publish ports, fenced message routing, independent cessation, lane termination and unhealthy-lane recovery. The deterministic fake trials and scratch isolation checks can proceed independently.

Resolve the author and its substrate adapter using the configured agent loader. Follow the existing `AgentSession` composition of `resolveActivation`, `resolveExecutionPlan`, cartridge policies, `SubstrateViewLayer.buildView` and `DefaultPromptAssembler`; make `programming` a trusted host selection for work, not a property inferred from external text. Do not rely on the existing room compatibility branch that may pass an empty cartridge-policy list or continue after a retrieval error. The view layer is directly callable without a Room. Create a fresh request-local context; never share result buffers between lanes. Feed bounded, marked task context through the headless loop input, outside static rules and tool selection. Refuse missing runtime-required scopes, blocked programming policies, configuration failures or adapter errors with a stable named blocker. Check scope policy resolution with representative fixture data and record a layer defect if covered scopes do not differ by activity. Emit only a successful-load event with elapsed time, estimated token count and covered scope count. Never emit raw view content or per-scope names.

## Measurement

Use a read-only SQLite connection against a supplied scratch snapshot. Join sessions to work IDs and the stored adapter kind, with an explicit `unknown` row for missing historical kinds. For a work that changes adapter, attribute per-session metrics to the actual kind and label work-level PR/review outcomes `mixed` instead of double-counting. Fetch PR and review data through a read-only fixture-able port pinned to the work's recorded PR. Missing remote evidence remains unknown. Report sessions, iterations, execution time, stop reasons, opened PRs, documented review rounds and requested changes. A review round is a distinct reviewed head with eligible review evidence. Keep raw results and an operator-dedicated capture of memory or resource use outside the repository. After the lane decision is satisfied, match cohorts by task size and difficulty with a predeclared range, use two authors per adapter, and explicitly record differences in checkpointing, resumption, context access and compaction. No adapter quality conclusion follows solely from a small sample.

## Dependencies and execution

Fake lifecycle scenarios and read-only fixture reporting can start before adapter selection lands. Real deadline tests wait for #419 abort provenance. Parallel mixed execution waits for #411 and #419 routing. The resume scenario waits for #410 and requires a covered handoff. A local scratch run or an approved read-only GitHub query is a separately authorized verification action. No production schema change or live activation belongs to trial-only work.
