# Evidence-first verification pilot for pair mode

## Architecture

This pilot consumes candidate slices of #275 and the baseline collection tracked in #377. The clean base includes WorkStore, the low adapter, the VM runner seam and existing Bun suites, but does not implement the proposed pair pool. Qualify acceptance evidence at the actual store and adapter boundaries after the relevant candidate slice exists. Use one private evidence index per candidate commit and preserve negative or missing observations. The index identifies case id, source commit, test command, test framework, exit status, tested behavior, real or fake dependency boundary, artifact digest where needed, gate verdict, and limitations. Do not include secrets, private checkout paths, or raw deployment data in reusable templates.

Use a deterministic operation-sequence fixture with a small reference model (free, leased, quarantined). Generate bounded sequences of reserve, competing reserve, release, crash, restart, recover, and stale-generation operations over known seeds; record a seed on any failure. Temporary real SQLite, independent store connections and at least one barrier-controlled contention case test reservation atomicity. Exercise four capacity slots plus excess work, reuse after proved cessation, and preservation of queue, generation and caps at full capacity. Run one isolated mutation per property family to show a test detects the targeted regression, preferably by replacing the fence check in a disposable checkout and replaying the original tests. A test that cannot discriminate the mutation must be reported as limited. Use a fake worker that requires HOME, leaves stale marker and credentials in the retired session, and verifies the next session sees only its own values and approved history. A fake is evidence for orchestration; an independently authorized real VM smoke is reported separately.

Collect baseline and pilot samples with the same fields: changes examined, candidate time to first substantive review, review and rework cycles, verified missed and false gate signals, absolute review time where measured, source and gaps. No baseline sample is imputed. Use #377 if its result is available and fits the definitions; otherwise record why it is missing and keep the pilot assessment descriptive. An independent reviewer must read exact-head evidence and identify gaps before recommending expand, adjust or stop. Retain original gate status and all unsupported boundaries.

## Test strategy

Test real SQLite transactions and controlled concurrent callers separately from scheduler test doubles. Use fake process and VM seams for marker and credential checks. Preserve a real versus fake column for each observation. Mutation evidence is generated in disposable source trees with full proof of restoration. Report live smoke only after verifying the real pinned binary and test environment under separate authorization. Evidence review and measurement are documentation work and need no product change.
