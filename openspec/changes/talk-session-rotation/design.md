# Rotate long-lived CLI talk sessions

## Architecture

`src/cli.ts` currently calls `SessionManager.openSession` for normal CLI talk; headless review creates and ends a separate `review` session. `SessionManager.newSession` and `closeSession` dispatch `onEnd` asynchronously; neither establishes the completion order needed here. The CLI manager currently supplies no `onEnd`. `buildSessionEndHandler` already summarizes to the memory store, but its current wrapper catches failures. `SessionStore.countTurns` excludes soft-deleted turns after compaction. `SessionRecord.started` is durable.

Add opt-in room overrides under `session.talkRotation` and effective defaults of `maxAgeMs=86400000` and `maxTurns=200`. The turn default is a proposed design decision. Positive safe integers only. Compare elapsed age and persisted count at entry using inclusive thresholds. One user or assistant row is one turn; count soft-deleted history, since compaction must not extend the lifetime. Hard reset can restart the count. A simultaneous age and turn breach selects `age`; an invalid or future start timestamp does not trigger age rotation and does not disable a valid turn check.

At the normal talk CLI entry, serialize by canonical session-store path and agent across processes. Hold the talk lock through session selection, summary, provider/tool loop, and final turn persistence. Release it in `finally`. A contender gets a bounded busy result before touching the session, allowing a caller to retry. Headless reviews are out of scope. The existing `--loop` path opens a talk session while preparing mail context, then writes to channel `loop` inside `runLoopMode`. Leave its loop channel and mail behavior unchanged, and do not rotate a talk session from it. Keep existing reset/new-session callers unchanged.

A talk-only rotation coordinator receives the existing session, effective limits, injected clock, and an awaited continuity callback. Use a durable rotation claim in SQLite scoped to the old session id before invoking the callback; competitors must not invoke it a second time. The callback reuses the existing summary implementation with propagated failures and returns exact old-session completion evidence. After confirmed completion, end the old session and create the replacement in one transaction. A same-process failure or crash during a running claim leaves the old session and transcript intact and the rotation in a visible recovery-required condition. Never blindly repeat a summary whose external write may already have committed. Recovery must prove whether it was written before retry or completion; automatic cross-store exactly-once retry requires a separate idempotent storage contract. Empty history is an explicit successful no-op. If the configured memory path cannot persist a nonempty summary, fail closed and report the reason.

The loader performs its existing bootstrap before selecting a session. Provide the newly written summary through the existing prompt-bootstrap/recall boundary after rotation so the first response can see it without waiting for another command. Emit one structured event after replacement commits, with `oldSessionId`, `newSessionId`, and `reason` and no transcript content. Idle rooms are rotated on their next talk. Track very old dormant rows separately in rollout measurements; they do not trigger a background sweep.

## Test strategy

Fake clock for age and exact threshold tests. Use a temporary real SQLite database for soft deletes, lock contention, crash-marker recovery, and completed rotation. Use controlled fake providers/memory stores to test delayed and failing summaries and first-response context. Exercise both plain CLI and any loop path writing `talk`; expect untouched review, castle and Telegram sessions. Record post-deploy age and daily compaction spend in a separate owner-authorized exercise.
